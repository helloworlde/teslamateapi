## Project Overview

TeslaMateAPI is a Go REST API that exposes TeslaMate's PostgreSQL database and MQTT broker data via two versioned API families. It runs on port 8080 with base path `/api`.

- **Framework**: Gin (HTTP)
- **Database**: PostgreSQL via `database/sql` + `lib/pq`
- **Message Broker**: MQTT (Paho client) — backs the `/v1/status` endpoint
- **Docs**: Swagger/OpenAPI generated by swag, served via Scalar UI at `/api/docs/scalar`

## Common Commands

```bash
make docs       # Regenerate Swagger: swag init -g server.go -d internal/server,...
make fmt        # go fmt ./...
make vet        # go vet ./internal/... ./cmd/...
make test       # go test ./internal/... -count=1
make build      # Builds to ./bin/teslamateapi
make check      # fmt + vet + test + build (run before committing)
make clean-docs # Remove generated swagger.json/yaml
```

Run a single test package:
```bash
go test ./internal/api/v2/... -count=1 -run TestFunctionName
```

## Architecture

### V1 API (`internal/api/v1/`)
Raw TeslaMate database queries. Response envelope: `{"data": {...}}` or `{"error": "message"}`. **V1 always returns HTTP 200**, even on errors (legacy behavior — do not change).

### V2 API (`internal/api/v2/`)
Aggregated analytics with a strict service/repository layering:
- `v2_handler.go` — HTTP handlers + builder interfaces
- `v2_*_service.go` — business logic, implements `V2*Builder` interface
- `v2_*_repository.go` — SQL queries
- `v2_*_test.go` — unit tests using fake builders

**V2 returns proper HTTP status codes** (400, 404, 500, etc.). All V2 responses must be wrapped in `V2APIResponse{Data, Meta}`.

### Shared packages
- `internal/apicommon/` — `HandleSuccessResponse`, `HandleErrorResponse`, global `DB` handle, `AppUsersTimezone`, `IsReady` atomic flag
- `internal/nullx/` — Null-safe wrappers for SQL nullable columns (`nullx.String`, `nullx.Int64`, etc.) — always use these for nullable DB columns, never `sql.Null*` directly
- `internal/config/` — `Env()`, `EnvAsBool()`, `EnvAsInt()` helpers for reading env vars

## V2 Design Rules (from `docs/api-design-spec.md`)

1. Every field must answer "what decision does a user make with this?" — no filler fields
2. No meaningless averages; prefer min/max/median/percentiles
3. All numeric fields must carry explicit units in the name: `_km`, `_kwh`, `_pct`, `_seconds`
4. Never hardcode currency or timezone — both must be configurable
5. Invalid parameter combinations → 400 with `code: PARAM_DEPENDENCY_VIOLATION`
6. Default params must make the endpoint "naked-callable" (no query params → meaningful response)

## Testing Pattern

Tests use fake builder structs instead of mocking the DB:

```go
type fakeV2SummaryBuilder struct {
    response V2SummaryResponse
    err      error
}
func (b fakeV2SummaryBuilder) BuildSummary(ctx context.Context, carID string, tr V2TimeRange) (V2SummaryResponse, error) {
    return b.response, b.err
}
```

HTTP layer tested with `httptest.NewRecorder()` + `httptest.NewRequest()`.

## Adding a V2 Endpoint

1. Define types with swag `@name` annotations in `v2_models.go`
2. Add `V2*Builder` interface to `v2_handler.go` + wire HTTP handler
3. Implement service (`v2_*_service.go`) + repository (`v2_*_repository.go`)
4. Register route in the v2 router setup
5. Add unit tests with fake builders
6. `make check` → `make docs` → test with curl

## Key Environment Variables

| Variable | Default | Notes |
|----------|---------|-------|
| `DATABASE_HOST` | database | Required |
| `DATABASE_USER` | teslamate | Required |
| `DATABASE_PASS` | secret | Required |
| `ENCRYPTION_KEY` | — | Required; decrypts Tesla tokens |
| `MQTT_HOST` | mosquitto | Required unless `DISABLE_MQTT=true` |
| `TZ` | Europe/Berlin | IANA timezone; used for all V2 time-window calculations |
| `DEBUG_MODE` | false | Gin debug mode + verbose response logging |
| `DISABLE_MQTT` | false | If true, `/v1/status` returns 501 |

## Readiness & Health

- `/api/ping` — always 200 `{"message":"pong"}`
- `/api/healthz` — always 200 (liveness)
- `/api/readyz` — 503 until DB ping succeeds; controlled by `apicommon.IsReady` atomic bool

## Swagger Workflow

After any handler or struct annotation change:
```bash
make docs
# Verify internal/docs/generated/swagger.json updated
```

swag entry point is `internal/server/server.go`; it scans `internal/server`, `internal/api/v1`, `internal/api/v2`, `internal/apicommon`, `internal/docs`.

## Build & Docker

Binary is statically compiled (`CGO_ENABLED=0`). Version injected at link time:
```
-ldflags="-X github.com/tobiasehlert/teslamateapi/internal/config.APIVersion=${version}"
```

Multi-arch Docker target platforms: `linux/amd64`, `linux/arm64`, `linux/arm/v7`.
